# ソートの動きを見る — VBAで読むアルゴリズム

ソートアルゴリズムの動きを棒グラフで可視化しながら、**対応するVBAコードの実行行を同じ画面で追える**授業用ツール。
教員がプロジェクタで投影して説明し、生徒も自分のPC・スマホで触る想定。

対象は「If・ループ・最大最小・線形探索・配列」まで既習のプログラミング初級者。

配布先: <https://mkt918.github.io/sort-visualizer/>

## 使い方

`index.html` をブラウザで開くだけ。ビルド不要・外部依存ゼロなので、
ネットワークが無い教室でも、`file://`（ファイルをダブルクリック）で動く。

| 操作 | キー |
|---|---|
| 再生 / 一時停止 | スペース |
| 1ステップ戻る / 進む | ← / → |
| データを作り直す | R |

- **モード**: トップバーの3択で切り替える。▶ ソロ（1つのアルゴリズムの動きをじっくり見る）／
  🏁 レース（2つを同時に走らせて比べる）／✎ じぶんで書く（生徒が自分のソートを一から書いて動かす）。
- **アルゴリズム**: 【まず理解する】バブル・選択・挿入／【動きを見る】シェル・クイック・マージ・ヒープ の7種。
- **データ**: ランダム / 逆順 / ほぼ整列済み / 重複多め。本数は 8〜60。
- **速度**: 1〜120の連続スライダーではなく、1/2/4/8/16/32/64（step/秒）のボタン。
  よく使う低速域（1〜5）が選びにくいという問題があったため、倍々の離散ボタンに作り直した。
- **✎ 編集する**: バブル・選択・挿入・シェルの4種は、コアループのVBAをその場で書き換えて「実行」できる。
  簡易インタプリタが実際に構文解析・実行して、同じ画面・同じ操作で動きを見せる。クイック・マージ・ヒープ
  （複数Sub・再帰）は対象外（下記「編集して実行」参照）。
- **コードをコピー**: 画面のVBAを、A列読み込み・B列書き出しまで含んだ完全版でクリップボードへ。
  Excelで `Alt+F11` → 挿入 → 標準モジュール → 貼り付け → `F5`。詳しくは [excel/Excelでの使い方.md](excel/Excelでの使い方.md)。
- **🏁 レース**: トップバーの「ソロ／レース」で切り替える。同じ初期データを2つのアルゴリズムで
  同時に走らせ、片方が完走した瞬間に両方止める。ステップ数の差がそのまま計算量の差として見える。
  既定はバブル vs クイック。
- **🔊 効果音**: 比較・交換のたびに「ポコッ」という短い音が鳴る（Web Audio APIでその場で合成、
  外部音源ファイルなし）。音の高さは値に対応するので、動きが速いアルゴリズムほど軽快に鳴る。
  再生系ボタンの隣の🔊ボタンでON/OFFを切り替えられ、設定はブラウザに記憶される。
- **スマホ対応**: 320px幅まで横スクロールなしで動作を確認済み。タッチ端末（`pointer: coarse`）では
  ボタンが自動で44px以上のタップサイズになる。
- **✎ じぶんで書く**: 用意されたコードを改造する「編集して実行」とは別に、白紙から自分のソート
  アルゴリズムを書いて動かすモード。予測変換ポップアップ・部品パレット・自動インデント/自動閉じ・
  書きながらの構文チェックでアシストする。5段階のミッション（2値の入れ替え→最小値探索→交換→
  選択ソート完成→自由課題）を段階的にこなし、複数データでの自動採点と、バブル・選択・クイックとの
  比較回数の一覧が出る。詳しくは下記「じぶんで書くモード」を参照。

`tests.html` を開くと自己検証が走る（現在 93/93 パス）。

## 設計の核心

### 1. ステップ列の事前生成

アルゴリズムは「実行」せず、`generate()` が**全ステップを配列に吐き出す**。
再生・一時停止・1ステップ戻る・シークバー・レースは、すべてこの配列のインデックス操作に還元される。個別実装しない。

各ステップは `{ line, array, mark, sorted, vars, counters, narration, extra }` を丸ごと保持する。
差分ではなくスナップショットにしてあるので、逆行とシークが自明に実装できる（上限 60000 ステップでガード）。

`extra` はマージソートのように、値が「配列 `a` にはまだ反映されていないが、作業用配列に退避されて
消えてはいない」場合に使う汎用フィールド（単純な swap 系アルゴリズムの `tmp` 1個だけなら `vars.tmp` で足りる）。

レースモード（`js/race.js`）は、この同じ `steps` 配列を2本、1ステップずつ同速で進めるだけの薄いラッパー。
どちらかが最後のステップに達した瞬間に両方停止し、もう片方の到達位置をそのまま表示する。

### 2. VBAソースが唯一の正 — 行番号は自動採番

JS実装とVBAコードの二重管理がこのツール最大のリスク。行番号をJS側にベタ書きすると、VBAを1行足した瞬間に全部ズレる。
そこで **VBAソースの行末に `'#マーカー` を書き、`SV.buildVba()` がそれを剥がして行番号を採番する。**

```vba
    For i = 0 To n - 2                        '#outer
        For j = 0 To n - 2 - i                '#inner
            If a(j) > a(j + 1) Then           '#compare
```

`generate()` は `rec.step(L.compare, ...)` と書く。行番号がコードから外れることが構造的に起きない。
マーカー名を綴り間違えると `line` が `undefined` になり、`tests.html` の「行番号がコードの実在行を指す」で必ず落ちる。

クイック・マージ・ヒープは手続きが複数（呼び出し役＋本体、マージはさらに結合処理）に分かれるため、
共通の `SV.wrapVba()` は使わず、それぞれの `js/algorithms/*.js` の中で全文を自前で組み立てている。

### 3. 表示用とExcel貼り付け用を1ソースから切り出す

画面に出すのは並べ替えのコアループだけ（初級者に読ませたいのはそこだけ）。
コピーボタンが渡すのは、A列読み込み・B列書き出しを含む**そのままF5で動く完全版**。
`coreFrom` / `coreTo` で表示範囲を切り出しているだけなので、両者がズレることはない。

配列サイズと `n` は画面の本数から生成するので、棒を30本にすればコードも `Dim a(29)` / `n = 30` になる。

`excel/SortDemo.bas`（7アルゴリズムをまとめた配布用ファイル）だけは、A列の件数を自動で数える形
（`n = Cells(Rows.Count, 1).End(xlUp).Row`）に書き換えている。生成方法は
[excel/Excelでの使い方.md](excel/Excelでの使い方.md) の「開発者向け」を参照。

### 4. コード編集して実行 — 簡易VBAインタプリタ

`js/interpreter.js` が、生徒が編集したVBA（コアループのみ）を実際に字句解析・構文解析して1行ずつ実行し、
`generate()` と全く同じ形の `steps[]` を吐き出す。だから player.js / render.js は「手書きの generate() か、
インタプリタの実行結果か」を一切区別しない。

対応しているのは **単一Sub・非再帰**のバブル・選択・挿入・シェルの4つだけ。For/Next、Do While〜Loop、
If/Then/Else/End If（単一行・ブロックの両方）、Exit Do、代入（スカラー・配列とも）、四則演算・`\`・Mod・
比較演算子・カッコに対応する。クイック・マージ・ヒープは複数Subにまたがる再帰構造で、一般化した解釈が
ずっと難しくなるため対象外（`supportsInterpreter: false` を立てて、編集ボタンごと隠す）。

未編集のコードをそのままインタプリタに通すと、手書き `generate()` と**完全に同じ比較回数**になることを
`tests.js` でクロス検証している（4アルゴリズム×4データパターン×8サイズ＝128ケース）。
実行結果の「交換」カウンタは、インタプリタでは「配列への書き込み回数」（`tmp` を経由する3行スワップなら
書き込みは2回）を数えるため、手書き版の「論理的な交換回数」（同じスワップを1回と数える）とは
一致しない。これは定義の違いであって不具合ではない——ラベルを「交換」で固定せず、`swapLabel`/`swapNote`
で言い換えられるようにしてある（マージソートの「書き戻し」表示と同じ仕組み）。

構文・実行時エラー（未対応の記号、対応するNext/Loop/End Ifがない、未定義変数、配列範囲外、無限ループ）は
すべて日本語のメッセージと（分かる場合は）行番号付きでエラー欄に表示し、実行前の状態は変えない。

### 5. じぶんで書くモード — 自由記述インタプリタとミッション

「編集して実行」は既存アルゴリズムの改造だが、「✎ じぶんで書く」は白紙から自分のアルゴリズムを
組み立てさせる体験そのものが目的。既存の `js/interpreter.js` を土台にしつつ、自由記述で
致命的になる穴を今回ふさいでいる。

- **配列は `a` のみ。** `Dim w` や複数配列は今回のスコープ外。`w(0)` のように書くと
  「配列は a しか使えません」と実行前にエラーになる（黙って `a` を読む沈黙のバグを防ぐ）。
- **変数名は自動抽出する。** 自由記述では変数名を事前に決め打ちできないため、`collectVarNames()` が
  代入先・For変数をコードから拾って変数ウォッチに表示する。
- **比較カウントは「配列要素を含む比較だけ」を数える。** `j >= 0` のような添字チェック単体は
  数えず、`a(j) > tmp` のように配列要素が絡む比較だけを数える。これは手書き `generate()`
  （例: `insertion.js` は `a(j) > tmp` の箇所だけ数える）と定義を揃えるための決定で、
  「あなたのコード」と既存アルゴリズムの回数比較が意味を持つのはこの統一があるから。
- **交換カウンタは「書き込み」という名前にしてある。** インタプリタは配列への書き込み（`a(i) = ...`）を
  1回ずつ数えるため、`tmp` を経由する3行スワップは書き込み2回になる。一方、手書き `generate()` は
  同じ交換を論理的に1回と数える。同じ処理でも数え方が違うため、ラベルを「交換」で固定せず
  「書き込み」としている（既存の「編集して実行」の `swapLabel` の仕組みと同じ考え方）。
- **文法を3つ拡張した。** `And` / `Or` / `Not`（VBAの実際の仕様どおり非短絡評価）、`Exit For`、
  `While〜Wend`。詳しくは下記「編集インタプリタの対応文法」の表を参照。
- **ミッションは5段階。** `js/missions.js` に `{id, title, prompt, starters, judge}` として定義。
  ミッション1〜3は選択ソートの部品（交換・最小値探索・交換の実行）を1つずつ、ミッション4で
  それを繰り返して選択ソートを完成させ、ミッション5は手段を問わない自由課題。ミッション4・5は
  8種類の固定テストデータ（乱数・逆順・ほぼ整列・重複多め・要素数1や2など境界値を含む）＋
  今表示中のデータで採点する。ミッション5だけ、合格後にバブル・選択・クイックとの回数比較表を出す。
- **保存はlocalStorage。** ミッションごとにコードを自動保存する。共有PC教室を想定し、
  「保存内容を消す」ボタンで明示的にリセットできるようにしてある。
- **エディタはtextarea + アシスト。** contenteditableではなく既存の「編集して実行」と同じ
  `<textarea>` を土台にした（日本語入力の変換確定が素直に動くことを最優先したため）。
  予測変換ポップアップは `compositionstart`〜`compositionend` の間、候補計算そのものを止めて
  IME変換中に暴発しないようにしている。`keydown` ハンドラは `e.isComposing`（と後方互換の
  `keyCode === 229`）を最初にチェックし、変換中は一切のキー横取りをしない。

**キー操作**

| キー | 動き |
|---|---|
| Enter | 改行。直前が `For … To` / `If … Then`（ブロック）/ `Do While …` / `While …` なら、閉じ行（`Next 変数` / `End If` / `Loop` / `Wend`）も自動で入る |
| Tab | 予測変換の候補が出ていれば先頭を確定。出ていなければ4スペースのインデント |
| Shift+Tab | インデントを1段戻す |
| Esc | 予測変換の候補を閉じる |
| ↑ ↓ | 常にカーソル移動（予測変換には奪わせない） |

予測変換の候補は**2文字以上**打ったときだけ出る。`i` や `n` のような1文字の変数では出ない。
複数候補があるときはクリックで選ぶ（候補の中を↑↓で移動する操作はない。先頭候補が Tab で入る）。

## アルゴリズムの追加方法

`js/algorithms/<id>.js` を作り、`SV.algorithms.<id>` に以下の形で登録して、
`index.html` と `tests.html` の両方にスクリプトタグを、`js/app.js` の `ORDER` にIDを足す。

```js
SV.algorithms.insertion = {
  id: 'insertion', name: '挿入ソート',
  tier: 'basic',              // basic（理解させる）| advanced（動きを見せる）
  summary: '…',
  watchVars: ['i', 'j', 'tmp'],
  order: 'O(n²)',
  // 理論値がきれいな式になるなら theoryNote + theoryCompare(n)、
  // データ次第で変わるなら theoryLabel(n) で完全な文を返す（shell/quick/merge/heap を参照）。
  theoryNote: 'n(n-1)/2',
  theoryCompare: function (n) { return n * (n - 1) / 2; },
  // 「交換」カウンタの意味が違う（マージソートの「書き戻し」など）場合だけ上書きする。省略すれば既定の「交換」。
  // swapLabel: '書き戻し', swapNote: 'w から a へ書き戻した回数',
  // 複数Sub・再帰で簡易インタプリタが対応できないアルゴリズムだけ false にする。省略すれば true。
  // supportsInterpreter: false,
  vba: function (n) { … SV.wrapVba(…) + マーカー付き core … },
  generate: function (rec, L) { … VBAと1行ずつ対応させて書く … }
};
```

`generate` は**必ずVBAと同じ順序で書く**。速いJSではなく、VBAの写像であることが要件。
独自の最適化（早期終了など）をJS側だけに入れると、画面のコードと動きが食い違う。

追加したら `excel/SortDemo.bas` の作り直しも忘れないこと（下記「Excel連携」参照）。
単一Sub・非再帰なら `supportsInterpreter` を省略するだけで「編集して実行」が自動的に使えるようになる
（`tests.js` のクロス検証も自動的に対象へ加わる）。

## 決めたことと、その理由

- **Webフォントを使わない。** Cobalt テーマ本来の Space Grotesk / Inter / JetBrains Mono ではなく
  システムフォントスタックを採用した。ネットワークが無い教室で `file://` から開いても崩れないことを優先した。
- **ESモジュールを使わない。** `type="module"` は `file://` でCORSに阻まれる。
  クラシックスクリプト＋グローバル名前空間 `SV` にすることで、ダブルクリックで開ける。
- **棒の5状態は明度を階段状に離してある**（未処理80 → 交換70 → 比較58 → 確定45 → 基準33）。
  教室のプロジェクタは色再現が悪く、色相だけで分けると後ろの席から判別できない。白黒に潰れても読める。
- **数値ラベルは25本以上で自動的に隠す。** 本数を増やすと潰れて逆に読めなくなる。
- **`.bas` のダウンロードボタンは付けていない。** VBEの「ファイルのインポート」はANSI（日本語環境ではCP932）で
  読むため、ブラウザからUTF-8で吐くと日本語コメントが必ず文字化けする。
  アプリ側はクリップボード（Unicodeで正しく貼れる）に一本化し、`.bas` はビルド時に
  CP932に変換した実ファイルとして `excel/` に置いている。
- **交換の途中で同じ値の棒が2本並ぶのは仕様。** `tmp = a(j)` → `a(j) = a(j+1)` の間、配列には一時的に
  同じ値が入る。これはVBAの実際の挙動そのもので、「なぜ tmp が要るのか」が目で見える教材上の要点。
- **クイック・マージ・ヒープのコードは「参考」扱い。** 再帰は未習前提なので、読ませることより
  動きの派手さを楽しませる位置づけにしてある（`tier: 'advanced'`）。この3つだけ「編集して実行」も対象外。
- **レースは「片方が完走したら両方止める」。** 最後まで両方走らせるのではなく、勝敗が付いた瞬間に
  止めて負けている側の到達位置を見せることで、ステップ数の差＝計算量の差を強調している。
- **`excel/SortDemo.bas` の生成はNode→Pythonの2段構え。** アルゴリズムのロジックは
  `js/algorithms/*.js` の一箇所だけに持たせたい（Webアプリと配布用ファイルで別々に書くと必ずズレる）。
  一方でNode標準ライブラリはCP932への変換手段を持たないため、UTF-8生成はNode、
  CP932変換はPython（標準ライブラリで完結）という2段パイプラインにしている。
- **速度はプリセットボタン、連続スライダーではない。** 1〜120の連続スライダーは、実際によく使う
  低速域（1〜5）ほどピクセル幅が狭くて選びにくいという実害があったため、1/2/4/8/16/32/64の
  離散ボタンに作り直した（動画プレイヤーの再生速度ボタンと同じ発想）。
- **タップサイズは `pointer: coarse` で切り替える。** 画面幅（メディアクエリの `max-width`）ではなく、
  入力デバイスの特性で判定している。ワイドなタッチタブレットでも正しく44px以上になり、逆に
  投影用の狭いウィンドウでマウス操作しているときは34pxのまま情報密度を保てる。
- **操作は性質ごとに枠で区切る（`.control-group`）。** 以前は再生ボタン・速度ボタン7個・音声ボタンが
  無仕切りの1行に、データ設定とレース切替も無仕切りの1行に詰め込まれていて「とっ散らかっている」という
  指摘を受けた。再生／速度／初期データを別々の枠にし、ソロ⇄レースの切替はデータ設定に埋もれた単発ボタンから
  トップバーの2択セグメントコントロール（`.mode-switch`）に格上げして、画面全体が切り替わる操作であることを
  明示している。
- **`[hidden] { display: none !important; }` をグローバルに効かせている。** `.race { display: flex; }` の
  ように `display` を明示するクラスが `hidden` 属性と同じ詳細度で衝突し、`hidden` のはずのレース画面が
  実際には表示されたままになる不具合があった（DOMプロパティの `el.hidden === true` だけを見るテストでは
  検出できず、実ブラウザで画面を見て初めて発覚した）。以後どの要素に `hidden` を使っても確実に隠れるよう、
  リセットの先頭でグローバルに宣言している。
- **効果音は外部ファイルではなくWeb Audio APIでその場合成する。** `file://` でも動く方針を崩さないため。
  音の高さは並べ替え中の値に対数スケールで対応させてあり、テンポの良いアルゴリズムほど軽快な連続音になる
  （比較・交換を検知した瞬間に短いトライアングル波を1発鳴らすだけの単純な仕組み）。ブラウザの自動再生制限
  により、AudioContextの生成・再開は最初のユーザー操作（クリック）まで遅らせている。
- **モードは文字列 `'solo' | 'race' | 'studio'` で1本化した。** 3モード目を足す前は
  `raceOn` という真偽値だったが、モードが3つになった時点で「レースでない＝ソロ」という
  2値の前提が崩れるため、`state.mode` に置き換えた。
- **「じぶんで書く」モードは `js/studio.js` に隔離し、`app.js` からは
  `onEnter`/`onExit`/`onDataChanged` の3メソッドだけで委譲する。** `app.js` がこれ以上
  肥大化しないよう、モード固有のDOM参照・状態・localStorage操作はすべて `studio.js` 側に閉じている。
- **予測変換のエディタは `contenteditable` ではなく `<textarea>` にした。** 日本語入力の
  変換確定（Enterキー）を横取りせず素直に動かすことを最優先したため。既存の「編集して実行」の
  `<textarea id="codeEdit">` と同じ方針。
- **予測変換は Enter と ↑↓ を絶対に奪わない。1文字では候補を出さない。** 最初の実装は
  1文字打つだけで候補が開き、候補が開いている間は Enter / Tab / ↑ / ↓ を無条件に横取りしていた。
  その結果、VBAの主要な1文字変数 `i` `n` `a` がキーワードの前方一致に片っ端から衝突し、
  行末が英字で終わる行（＝コードの大半）で**改行できない**（`Next i` と打って Enter すると
  `Next If` に化ける）・**カーソルが上下に動かせない**という致命的な事故になった。
  対策として、候補は2文字以上でだけ出し、Enter は常に改行、↑↓ は常にブラウザ既定のカーソル移動、
  確定は Tab とクリックだけにした。「いつキーを奪うか」の判断は `keyAction()` という純関数に
  切り出して `tests.js` で固定してある（この判断を将来ゆるめるときの歯止め）。
- **候補ポップアップは textarea の下端をはみ出すなら上向きに反転させる。** 部品パレットや
  「実行して確かめる」ボタンに被って、ボタンのクリックが候補行の `mousedown` に吸われるのを防ぐ。
  textarea の外を `mousedown` したら候補を即閉じる（`blur` の遅延クローズだと、その隙に
  押されたボタンが候補に取られる）。

## 編集インタプリタの対応文法

`js/interpreter.js` が対応する VBA のごく一部のサブセット：

| 文法 | 対応 |
|---|---|
| `For 変数 = 式 To 式 [Step 式]` / `Next [変数]` | ○（ネスト可） |
| `Do While 式` / `Do Until 式` / `Loop` / `Exit Do` | ○（ネスト可） |
| `If 式 Then` （ブロック） / `Else` / `End If` | ○ |
| `If 式 Then 文` （単一行） | ○ |
| `While 式` / `Wend` | ○（`Do While〜Loop` と同じ意味。ネスト内では `Exit Do` は使えない＝実際のVBAの仕様どおり） |
| `Exit For` / `Exit Do`（ブロックの単一行 `If ... Then Exit For/Do` も含む） | ○（いちばん内側の対応するループだけを抜ける） |
| `And` / `Or` / `Not` | ○（実際のVBAと同じ**非短絡評価**。`j >= 0 And a(j) > x` は `j = -1` でも `a(j)` を評価するので範囲外エラーになりうる） |
| 代入 `変数 = 式` / `a(式) = 式` | ○（配列名は `a` のみ。他の名前はエラー） |
| 演算子 `+ - * \ Mod` / 比較 `< > <= >= = <>` / カッコ / 単項マイナス | ○ |
| `Select Case`、複数Subにまたがる `Call`、複数配列、文字列・真偽値、`Dim` 以外の宣言 | ×（今回は対象外） |

対応していない文法を書くと「〇〇が理解できません」「対応するForがありません」のように、
どこが分からなかったかを日本語で示して実行前に止まる（実行結果を壊さない）。

比較カウントは「配列要素を含む比較（`cmp` ノードの左右どちらかに `a(...)` を含む）」だけを数える。
`j >= 0` のようなスカラー同士の比較は数えない（「じぶんで書くモード — 自由記述インタプリタとミッション」参照）。

## GitHub Pages への公開

1. このフォルダを単独のGitHubリポジトリにする（`sort-visualizer` を想定）。
2. `git remote add origin <URL>` → `git push -u origin main`。
3. リポジトリの Settings → Pages で、ブランチ `main` / フォルダ `/ (root)` を指定。
4. 数分待つと `https://<ユーザー名>.github.io/sort-visualizer/` で公開される。
